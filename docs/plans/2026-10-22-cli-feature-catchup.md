# CLI compatibility audit — 2026-10-22

Cogpit now targets Claude Code 2.1.306 through Agent SDK 0.3.306 and supports the applicable additions in Codex CLI 0.163.0. These changes are local and unreleased.

## Comparison baseline and sources

The previous audit was [October 1, through Claude Code 2.1.287 and Codex 0.159.3](2026-10-01-cli-feature-catchup.md). This one covers Claude Code 2.1.288–2.1.306 and Codex stable releases 0.160.0–0.163.0.

Primary sources:

- [Claude Code changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md), entries 2.1.288–2.1.306.
- Agent SDK 0.3.306 TypeScript declarations (`sdk.d.ts`, `sdk-tools.d.ts`), diffed against 0.3.287.
- Codex release notes for 0.160.0 through 0.163.0, and the app-server JSON schemas generated by 0.159.3 and 0.163.0 (`codex app-server generate-json-schema --experimental`), diffed.
- Installed binaries: `claude --version` → 2.1.306; `codex --version` → 0.163.0. Live probes: headless SDK runs with nested subagents and `/usage` / `/context`, a raw app-server steer during a streaming reply, `model/list`, goal set/clear with `origin`.
- Transcripts on disk: record types, keys and file names written by Claude Code 2.1.288+ and Codex 0.160+ on this machine, compared with what the parsers and stores handle.

## Implemented

### Claude Code

| Change | Cogpit behavior |
| --- | --- |
| Claude SDK update | Dependency and lockfile move from 0.3.287 to 0.3.306. |
| API request records (2.1.300) | Transcripts now carry `api-request`, `api-request-blob` and `api-request-shape` records, 20–46% of the 256KB tail window on heavy sessions. `AgentFormat.isNoiseLine` drops them before the tail and `?before` byte budget and line floor, from `/api/watch` live updates (each `lines` event reports `skippedBytes` so web and iOS resume offsets stay exact), and from the status and metadata scans. Full-file loads still send them because undo and new-session offsets compare against the file; the parser skips them before `JSON.parse`. First tail page on real sessions: 10 → 21, 1 → 3 and 1 → 5 turns. |
| Subagent ids (0.3.306) | `task_started` binds a task id to its Agent call, and subagent frames carry `agent_id` equal to that task id. The prompt matching and provisional claims in `sdk-session.ts` / `subagentWatcher.ts` are removed. Two agents with identical prompts now bind to their own calls. |
| Nested subagents | Subagents have nested up to depth 3 by default since 2.1.219 (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`). `parent_task_id` now places each nested agent under its root Agent call with `parentAgentId`, indented in the sub-agent panel and the agents sidebar. |
| Agent tool `effort` (2.1.292) | Shown next to the model on the Agent call and the sub-agent panel ("Haiku 5.5 · low effort"), and on iOS. |
| Structured `/usage` and `/context` | The `local_command` record carries `contextUsage` / `usageReport`. They render as a context card (window use, stacked bar, per-category rows) and a usage card (per-limit meters, resets, extra-usage spend, recommendations) on web and iOS, through `/api/session-context` and `cogpit-memory context`. Older transcripts keep the text card. Recommendation `fix` values and context row `id`s exist only on the control-call replies, not in the transcript, so they are not used. |
| `overageEnabled` (2.1.295) | The rate-limit banner says whether extra usage is off or did not cover the request. |
| Idle compaction (2.1.290+) | The compaction marker labels the `idle` trigger. |

### Codex

| Change | Cogpit behavior |
| --- | --- |
| Compressed rollouts | Codex zstd-compresses rollouts idle for 7 days (`.jsonl.zst`); 1,186 of this machine's rollouts were compressed and invisible. `server/agents/transcriptFile.ts` (and cogpit-memory's copy) reads them through `node:zlib` under Bun and Electron. Listing, URLs and clients keep the plain `.jsonl` name; the plain file wins when both exist; `/api/watch` follows a resume that decompresses the file; undo writes a plain file and removes the `.zst`. cogpit-memory skips `.zst` on Node older than 22.15. |
| Steer cancels the streaming reply (`instant_interrupt` default-on in 0.163) | The cancelled `agentMessage` never gets `item/completed`, so its overlay stayed until the turn ended. `codexStreamAdapter` clears the thread's overlay when a `userMessage` item starts. Sequence confirmed live against 0.163. |
| Failed turns (0.160.1) | `task_complete.error` shows as the turn's reply after reload, on web, cogpit-memory and iOS. |
| Sub-agent rollouts (0.162) | Records before `session_meta.subagent_history_start_ordinal` are copied from the parent and are skipped, on web, cogpit-memory and iOS. Older converted rollouts that put the boundary at the end of the file are left whole. |
| Sub-agent model and effort (0.162) | Read from `SubAgentActivity` items, which also give the real thread id and completion. |
| Prompts only in `response_item` | Rollouts written since early October have no `event_msg user_message` records. Server prompt search, the Mission Control turn count, file-change turn indexes and the iOS parser read only that record and missed every prompt. They now share `codexPromptText` / `createCodexPromptReader` with the web parser, which skip injected context and the duplicate `user_message` older CLIs write. |
| Goal origin (0.160) | Goal set and clear send `origin: "user"`, so the model is told about the edit. |
| Models | The fallback catalog and iOS mirror `model/list` from 0.163: GPT-5.5 is gone, GPT-6 Sol and Luna Fast tiers read "1.5x speed". |
| Protocol | Generated protocol regenerated from 0.163.0. |

## Changes handled by existing integration

Claude: the slash-command set from `supportedCommands()` is identical on 2.1.287 and 2.1.306. Haiku 5.5 and the separate Haiku 4.5 row come from the live catalog. New wrapper keys (`requestRef`, `thinkingDisplay`, `interruptedByShutdown`, `mergedSendUuids`, and others) and the `dynamic_skill` attachment are ignored safely. Cogpit always passes a permission mode, so the 2.1.302 default change does not apply. Teammates are identified by `teamName`/`agentName` tags, so the 2.1.290 `agent_id` / `teammate_id` change does not affect them. Nothing in Cogpit gates on the CLI version, so `claude_code_version` on the initialize reply is unused. Cogpit has no Claude plugin install flow, so `reloadPlugins({ addPlugins })` has no caller. The configuration editor is raw text, so `idleCompaction` and `modelSettings[model].autoCompactWindow` need nothing.

Codex: `ServerRequest.json` is identical between 0.159.3 and 0.163.0. New notifications (`thread/readState/changed`, `thread/prediction/updated`) are experimental and Cogpit connects without the experimental API. Rollout record and item types match 0.159. `partial_answer` is a message phase and nothing in Cogpit reads phases. `code_mode_interrupt` and `cli_daybreak` became default-on with no host surface.

Terminal rendering, mods, the self-hosted runner, cloud and Remote Control, Windows, gateways, telemetry and Codex TUI, sandbox, daemon and voice changes are CLI or separate-product surfaces.

## Explicit boundaries

- Codex `turn/start` `parentTurnId` / `rootTurnId` are not sent. Cogpit lineage is per session; a parent turn id exists only for a Codex parent on the same app-server, and nothing reads the result back.
- `run_id` on Claude task events is unused. A subagent resumed in a new process binds to the call id its new `task_started` carries and forwards its transcript again from the start.
- Sessions Cogpit did not drive (terminal sessions) do not show nested agents; `agent-<id>.meta.json` has `parentAgentId` if that is wanted later. iOS files nested agents under the root agent's card, flat.
- Sessions recorded under the old prompt matching keep any wrong bindings already written.
- A Codex sub-agent's first prompt is stored encrypted (NEW_TASK) and does not show.
- The Codex web parser keeps only the first prompt of each turn, so messages sent while a turn runs (follow-ups, crew-chat wakeups) are missing from the web transcript and cogpit-memory search. Fixing it changes turn structure, which undo and paging depend on.
- Codex usage cost on sub-agent rollouts still uses its existing heuristic for the copied parent history.

## Verification

- `bun run test`: 721 files, 11,347 tests; a final run had six 5-second timeouts under load in app-server, shim, plugin-store and workspace-transfer tests, all passing when rerun on their own (146 tests). `bun run test:public`: 9,595 tests passed; both run with `COGPIT_PORT`, `COGPIT_SESSION_ID` and `COGPIT_ORCHESTRATION_ROOT` unset.
- `packages/cogpit-memory`: 110 tests passed, each file run on its own.
- Lint, both typecheck sets, `check:agents` (re-seeded), `check:codex-protocol`, `check:architecture`, `check:cogpit-memory-sync`, `check:cogpit-skill-sync` and `check:duplicates` passed.
- iOS: `swift run cogpit-checks` passed 528 checks. No simulator or device run.
- Live, Claude 2.1.306: two subagents with identical prompts and a nested subagent bound by task id, matching the CLI's `agent-<id>.meta.json`; `/usage` and `/context` headless runs supplied the card payloads.
- Live, Codex 0.163.0: steer during a streaming reply (cancelled item never completes), `model/list`, goal set and clear with `origin`.
- Browser QA on standalone builds with temporary data directories: nested and twin subagents, the context and usage cards, and a compressed Codex session paging without gaps.
- Not exercised: the Electron app, remote devices, and a Claude team session (none on this machine).
